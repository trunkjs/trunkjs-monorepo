# @trunkjs/form

> Legacy-Hinweis: Die gepflegte Agent-Dokumentation liegt unter `skills/form-usage/SKILL.md`.

## Zweck

`@trunkjs/form` bietet `<tj-form>` als AJAX-fähigen Ersatz für ein natives `form` sowie `FormScope` für beliebige bestehende DOM-Container.

```ts
import { TjForm, registerFormController } from '@trunkjs/form';

registerFormController('contact-api', {
  args: { endpoint: '/api/contact' },
  onLoad: async ({ form }) => {
    form.data = await loadDraft();
  },
  onSubmit: ({ formData, args }) => fetch(String(args.endpoint), { method: 'POST', body: formData }),
  onError: ({ context, phase }) => (phase === 'submit' ? saveDraft(context.data) : undefined),
});

const form = new TjForm();
form.controller = 'contact-api';
form.innerHTML = '<input name="name"><input name="topics[]">';
document.body.append(form);
```

## APIs

- `data` und `value`: flaches `Record<string, unknown>`
- `map`: `Map<string, unknown>`
- `formData`: klassische `FormData`
- `remote`: Wrapper-Zugriff auf Controls und Gruppen
- `form`: internes natives `HTMLFormElement`
- `requestSubmit()`, `reset()`, `checkValidity()`, `reportValidity()`: native Form-Steuerung
- `controller`: Schlüssel eines global registrierten Lifecycle-Controllers
- `hooks`: direkte, elementspezifische Lifecycle-Hooks

Die Registry enthält Verhalten und Connector-Konfiguration, keine Formwerte. `registerFormController()` darf vor oder nach dem Verbinden des Elements laufen. Hooks: `onInit`, `onLoad`, `onValidate`, `onSubmit`, `onSuccess`, `onError`. Daten in `onLoad` explizit über `form.data`, `form.map` oder `form.formData` setzen.

`name[]` ergibt im Objekt/Map einen Arraywert unter dem Namen ohne `[]`. Radio- und Checkbox-Gruppen werden gruppiert.

```ts
form.remote.get('email')!.value = 'mail@example.com';
form.remote.get('*')!.validated = true;
form.remote.get('*')!.disabled = false;
```

## Custom Controls

Ein automatisch erkanntes Custom Control braucht:

```ts
interface CustomFormControlElement extends HTMLElement {
  value: unknown;
  disabled?: boolean;
  valid?: boolean;
  invalid?: boolean;
  validated?: boolean;
}
```

Zusätzlich muss es einen nicht-leeren Namen über Attribut oder Property liefern. `nte-input` ist damit ohne Adapter nutzbar. Für abweichende Value-Semantik ein `FormValuePluginInterface` implementieren und bei einer `FormValuePluginRegistry` registrieren.
