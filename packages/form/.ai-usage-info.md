# @trunkjs/form

## Zweck

Form-Helfer für das Lesen und Schreiben von Formularwerten über eine gemeinsame Scope-Klasse.

Der aktuelle Einstiegspunkt ist `FormScope`.
Er liest Werte aus einem DOM-Teilbaum und setzt Werte wieder zurück in passende Form-Elemente.

Zusätzlich gibt es mit `FormDataContainer` einen einfachen Proxy-basierten Container für `FormValue`-Objekte.

Die konkrete Logik pro Element-Typ liegt in Plugins.

## Import

```ts
import { FormDataContainer, FormScope, FormValue, FormValuePluginRegistry, formValuePluginRegistry } from '@trunkjs/form';
```

## Basisbeispiel

```ts
import { FormScope } from '@trunkjs/form';

const form = document.querySelector('form');
const scope = new FormScope(form!);

scope.data = {
  name: 'Max',
  newsletter: true,
  role: 'admin',
};

console.log(scope.data);

const registry = formValuePluginRegistry();
const customRegistry = new FormValuePluginRegistry();

const data = new FormDataContainer();
data.name.value = 'Max';
data.name.element = form?.querySelector('[name="name"]') ?? null;
```

## Plugin-System

Plugins implementieren `FormValuePluginInterface` und werden typischerweise über `FormValuePluginRegistry` verwaltet.

Wichtige Teile:

```ts
interface FormValuePluginInterface {
  supportedElements: Array<{
    tagnames: string[];
    types?: string[] | null;
  }>;

  getValue(element: HTMLElement): unknown;
  setValue(element: HTMLElement, value: unknown): void;
  skipChildren(element: HTMLElement): boolean;
}
```

`supportedElements` bestimmt, für welche `tagname`-/`type`-Kombinationen ein Plugin zuständig ist. Ein Eintrag kann dabei mehrere `tagnames` und mehrere `types` enthalten.

`skipChildren(...)` verhindert, dass der Parser unterhalb dieses Knotens weiter traversiert.

## Registry

```ts
import { FormScope, FormValuePluginRegistry, formValuePluginRegistry } from '@trunkjs/form';

const registry = formValuePluginRegistry();

const scope = new FormScope(rootElement, registry);

const customRegistry = new FormValuePluginRegistry();
customRegistry.addPlugins([]);
```

Die exported function `formValuePluginRegistry()` liefert eine Singleton-Instanz.
Diese Singleton-Instanz wird in `FormScope` standardmäßig verwendet.

## Standard-Plugins

Aktuell enthalten:

- `InputValuePlugin`
- `CheckboxValuePlugin`
- `RadioValuePlugin`
- `TextareaValuePlugin`
- `SelectValuePlugin`

Dateien liegen unter:

```text
src/lib/ValuePlugins/
```

## Verhalten von `FormScope`

- verarbeitet nur Kind-Elemente des übergebenen Root-Elements
- berücksichtigt nur Elemente mit `name`-Attribut
- `data` getter liefert ein flaches Objekt zurück
- `data` setter setzt nur Keys, die im übergebenen Objekt vorhanden sind
- bei Radio-Gruppen wird der Wert des selektierten Eintrags verwendet

## Agent-Hinweise

- Erweiterungen bevorzugt über neue Plugins und `FormValuePluginRegistry` umsetzen, nicht über Sonderlogik direkt in `FormScope`.
- Bestehendes flaches `name -> value`-Mapping beibehalten, solange nichts anderes verlangt ist.
- Neue Plugin-Dateien unter `src/lib/ValuePlugins/` anlegen.
