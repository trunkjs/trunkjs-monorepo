# @trunkjs/vite-demo-viewer

## Zweck

Vite-Plugin für den Demo-Viewer.

Dieses Paket ist nur für die Vite-/Node-Seite zuständig:
- Demo-Dateien finden
- Dev-Route mit HMR bereitstellen
- optional einen statischen Viewer mit generierter `index.html` bauen

Browser-Komponenten, `defineDemo(...)` und Demo-Typen kommen aus `@trunkjs/demo-viewer`.

## Serve-Modus

```ts
import { defineConfig } from 'vite';
import { tjDemoViewerPlugin } from '@trunkjs/vite-demo-viewer';

export default defineConfig({
  plugins: [
    tjDemoViewerPlugin({
      include: ['demo/**/*.demo.ts'],
      route: '/__tdemo',
    }),
  ],
});
```

Nur die konfigurierte Route wird bedient. `route: '/'` muss ausdrücklich gesetzt werden.

## Statischer Build

```ts
import { defineConfig } from 'vite';
import { tjDemoViewerPlugin } from '@trunkjs/vite-demo-viewer';

export default defineConfig({
  base: '/repository/',
  plugins: [
    tjDemoViewerPlugin({
      root: '..',
      include: ['packages/*/demo/**/*.demo.ts'],
      route: '/',
      title: 'Component demos',
      build: true,
    }),
  ],
  build: {
    outDir: '../dist/docs',
  },
});
```

`build: true` aktiviert bei `vite build` den eigenständigen Viewer. Der Build erzeugt `index.html` und die gebundelten Assets. Der Default ist `false`, damit Vite-Library-Builds, die das Plugin nur für die Entwicklung verwenden, unverändert bleiben.

Die Navigation aus `@trunkjs/demo-viewer` verwendet `#/demo/...`. Damit funktionieren direkte Demo-Links auf GitHub Pages ohne Server-Rewrites. Der Vite-`base` muss bei Projektseiten den Repository-Pfad enthalten.

## Optionen

- `include?: string[]` – Default: `['**/*.demo.ts']`
- `exclude?: string[]` – Default: Node-Modules und Dist
- `root?: string` – Scan-Wurzel relativ zum Vite-Root
- `route?: string` – Default: `'/__tdemo'`
- `title?: string` – Default: `'TDemo Viewer'`
- `build?: boolean` – Default: `false`

## Hinweise für Agents

- Demo-Dateien müssen auf `.demo.ts` enden.
- Verwende `defineDemo` bevorzugt aus `@trunkjs/demo-viewer`.
- Das Plugin enthält einen generischen `defineDemo`-Helper nur für Rückwärtskompatibilität.
- Serve und Build werden intern getrennt, aber über dieselbe öffentliche Plugin-Funktion konfiguriert.

## Demo-Quelltext

Das Plugin lädt den unveränderten Inhalt jeder `.demo.ts` über einen Vite-Raw-Import. Zusätzlich extrahiert es nicht minifizierte Bodies von `render`, `afterRender` sowie `onClick`, `onChange`, `onInput`, `onApply` und `validate` aus `controls: { items: [...] }` in `sourceInfo`. Auch mit `inspectable(...)` markierte, referenzierte Handler werden erkannt. Im normalen Lazy-Modus werden Quelltext und Snippets erst zusammen mit der ausgewählten Demo geladen; `source` bleibt der kompatible Full-Source-Fallback.
