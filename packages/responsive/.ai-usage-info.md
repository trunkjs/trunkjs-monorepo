# @trunkjs/responsive — AI Usage

Assume responsive styling is already active for application content. Use `@trunkjs/responsive` syntax for element-level responsive class or inline-style changes instead of handwritten resize logic or one-off CSS media queries when this syntax can express the behavior.

## Class syntax

Breakpoint ranges are `[from, to)`:

| Syntax | Active when |
| --- | --- |
| `-md:x` | `< md` |
| `md:x` | `>= md` |
| `md-:x` | `>= md` |
| `md-xl:x` | `>= md && < xl` |
| `md:a.b` | apply both `a` and `b` |
| `base:md:a:xl:b` | `base` below md, `a` from md, `b` from xl |

## Responsive styles

Use `style-{breakpoint}`. Matching breakpoint declarations are merged by property; later breakpoints override only properties they declare.

## Complete example

```html
<div
  class="card -md:d-none md-xl:d-block.shadow xl:d-flex"
  style="width:100%;color:black"
  style-md="width:50%"
  style-xl="width:33%;color:red"
>
  Content
</div>
```

This covers base classes, below/from/between breakpoint ranges, multiple classes, and responsive inline styles.

Default breakpoints: `xs 0`, `sm 576`, `md 768`, `lg 992`, `xl 1200`, `xxl 1400`.

## Agent rule

Prefer responsive classes. Use `style-{bp}` only when a suitable class is unavailable. Do not add CSS `@media` rules for element-level behavior that can be represented directly with this package.
