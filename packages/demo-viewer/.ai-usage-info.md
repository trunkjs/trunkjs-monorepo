# @trunkjs/demo-viewer

## Zweck

Browser-/Frontend-Seite des Demo-Viewers:
- Web Components
- `DemoRegistry`
- Demo-Typen
- `defineDemo(...)`

Vite-Setup, Dev-Route und Demo-Scanning gehören in `@trunkjs/vite-demo-viewer`.

## Import

Komplett registrieren:

```ts
import '@trunkjs/demo-viewer';
```

Oder gezielt nutzen:

```ts
import { DemoRegistry, defineDemo } from '@trunkjs/demo-viewer';
```

## Demo-Datei definieren

```ts
import { defineDemo } from '@trunkjs/demo-viewer';

export default defineDemo({
  title: 'Hallo',
  html: '<p>Demo</p>',
});
```

Oder als Render-Demo:

```ts
export default {
  title: 'Counter',
  render(root: HTMLElement) {
    root.textContent = 'Hallo';
  },
};
```

## Registry verwenden

```ts
import { DemoRegistry } from '@trunkjs/demo-viewer';

const registry = new DemoRegistry([
  { filename: 'forms/button.demo.ts', title: 'Button' },
]);

const nav = registry.getNavData();
```

## Hinweise für Agents

- Für Vite-Konfiguration immer `@trunkjs/vite-demo-viewer` verwenden.
- `<tj-demo-renderer>` rendert `html`, `markdown`, `wrapper_html`, `css` und `render(root)`.
- `Show code` priorisiert Raw-HTML, Raw-Markdown und den extrahierten `render`-Body; `source` bleibt der Full-Source-Fallback.
- `inspectable(handler)` macht referenzierte Action-Bar-Handler für die Build-Extraktion kenntlich; Inline-Handler werden automatisch erkannt.
- `env.toast.show(...)` zeigt einen temporären Toast; `env.toast.log(...)` schreibt in den persistenten Logging-Toast. `console.log` und `console.error` werden ebenfalls gespiegelt.
- Action-Bar-Items vom Typ `output` erscheinen im Logging-Toast statt in den Controls.
- Bei `css === undefined` oder `'default'` wird das Default-Stylesheet automatisch injiziert.
- Das Paket hat ein kleines lokales Mockup für Standalone-Entwicklung, aber Produktiv-/Projekt-Setup läuft über das Vite-Plugin.

## URL-basierte Ansichten

Die ausgewählte Demo bleibt im Hash `#/demo/...`. Der Query-Parameter `view` steuert die Darstellung:

- ohne `view`: vollständiger Viewer mit Navigation und Demo-Header
- `?view=fullscreen`: nur die gerenderte Demo über den gesamten Viewport
- `?view=source`: priorisierter Beispielcode (HTML, Markdown oder `render`-Body), mit vollständigem `source` als Fallback

`Escape` beendet `fullscreen` und `source`. Der Demo-Hash und andere Query-Parameter bleiben dabei erhalten.
