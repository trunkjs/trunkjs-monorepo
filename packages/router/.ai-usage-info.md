# @trunkjs/router

## Purpose

Frontend routing for TrunkJS Web Components.

Use it to:
- define routes directly on Web Components with `@route(...)`
- render the active route in `<router-content>`
- access route params, query, hash and metadata
- react to route changes with `withRouter` / `onRouteChange`
- generate URLs and navigate by route name or path
- choose SPA navigation or a full page reload

## Basic setup

```ts
import { Router, route, setDefaultRouter } from '@trunkjs/router';

@route({ name: 'home', path: '/' })
class HomePage extends HTMLElement {}

@route({ name: 'user', path: '/users/:id', meta: { title: 'User' } })
class UserPage extends HTMLElement {}

customElements.define('home-page', HomePage);
customElements.define('user-page', UserPage);

const router = new Router([HomePage, UserPage]);
setDefaultRouter(router);
router.start();
```

```html
<router-content></router-content>
```

The component attached to the matching route is inserted into `router-content`.

## Short decorator form

```ts
@route('/about')
class AboutPage extends HTMLElement {}
```

## Route params and metadata

```ts
import { withRouter, type RouteChange } from '@trunkjs/router';

class UserHeader extends withRouter(HTMLElement) {
  override onRouteChange({ route }: RouteChange) {
    console.log(route.params.id);
    console.log(route.query.get('tab'));
    console.log(route.meta.title);
  }
}
```

`withRouter` registers the route-change listener on connect, removes it on disconnect and immediately delivers the current route when one already exists.

## Generate URLs

```ts
router.url({
  name: 'user',
  params: { id: 42 },
  query: { tab: 'history' },
});
// /users/42?tab=history
```

## Navigate

```ts
router.navigate({ name: 'user', params: { id: 42 } });
router.navigate('/about');
router.replace({ name: 'user', params: { id: 42 } });
```

## Normal links

Use real anchors. Matching internal links are handled as SPA navigation automatically.

```html
<a href="/users/42">User</a>
<a href="/legacy" data-router-reload>Reload page</a>
<a href="/external-handler" data-router-ignore>Do not intercept</a>
```

## Full page reload route

```ts
@route({
  name: 'legacy',
  path: '/legacy/:id',
  navigation: 'reload',
})
class LegacyPage extends HTMLElement {}
```

Or override one navigation call:

```ts
router.navigate(
  { name: 'user', params: { id: 42 } },
  { navigation: 'reload' },
);
```

## Multiple components for one route

Register a route explicitly when more than one component should be rendered:

```ts
router.addRoute({
  name: 'settings',
  path: '/settings',
  components: [SettingsNavigation, SettingsPage],
});
```

## Route change event

```ts
router.addEventListener('routechange', (event) => {
  console.log(event.detail.route);
  console.log(event.detail.previousRoute);
});
```

## Agent hints

- Prefer `@route({ name, path })` on routable page Web Components.
- Pass decorated components to `new Router([...])`, call `setDefaultRouter(router)`, then `router.start()`.
- Use `<router-content>` as the main outlet.
- Use `withRouter` when a component outside the outlet needs `onRouteChange` or `this.router`.
- Prefer `router.url({ name, params })` for generated links and `router.navigate(...)` for programmatic navigation.
- Keep normal `<a href>` links; the router intercepts matching internal links.
- Use `navigation: 'reload'` only when a full document reload is required.
