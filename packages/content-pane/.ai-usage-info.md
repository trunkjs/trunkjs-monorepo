# @trunkjs/content-pane — agent reference

Turns flat Markdown-rendered HTML into nested sections, then replaces sections via `layout`.

**Creating a skill that uses ContentPane?** Copy/adapt `demo-skill/SKILL.md`; it is the canonical compact skill template and source for ContentPane rules/examples.

## Default rule

Use headings as the layout tree. **Omit `i` whenever it is inferable** and bind `layout` directly to the heading that owns the section. Defaults: `h1=2`, `h2=2`, `h3=3`, `h4=4`, `h5=5`, `h6=6`. Use `<hr layout>` only for an extra layout level with no own heading (e.g. one tile/grid wrapper around several child headings). An HR without explicit `i` uses the last fixed `i + 0.5`; plain `<hr>` is ignored. Use explicit `i` only when context cannot express the required level.

Markdown normally sets passdown attributes directly after the element:

```md
## Products
{: layout="page-section" section-class="wide"}
```

Equivalent source HTML: `<h2 layout="page-section" section-class="wide">Products</h2>`.

## `layout`

```text
layout="component"       inferred heading i; create section (preferred)
layout="3;component"     explicit i=3; create section
layout="+3;"             reuse/append to existing section at i=3
layout="-3;"             create no section; keep element in current container
layout="component#id.cls[attr=value]"  replacement selector
```

Example needing an extra non-heading wrapper:

```md
## Products
{: layout="page-section"}

---
{: layout="card-grid"}

### A
### B
```

Tree: `page-section(i=2) > card-grid(i=2.5) > h3 sections(i=3)`.

After `applyLayout()`:

```html
<page-section><h2>Products</h2><card-grid><hr hidden aria-hidden="true"><section><h3>A</h3></section><section><h3>B</h3></section></card-grid></page-section>
```

`section-*` configures the generated section and loses the prefix, e.g. `section-id`, `section-class`, `section-style`; `.section-*` classes are likewise moved without the prefix.
